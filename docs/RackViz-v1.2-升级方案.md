| D-02 | P0-02 | 添加数据库索引（迁移 v3） | 1h | 新增 `migrate_v2_to_v3()` 添加 7 个索引 | `EXPLAIN QUERY PLAN` 显示使用索引 |
| D-03 | P1-07 | 添加 UNIQUE 约束（迁移 v3） | 1h | `CREATE UNIQUE INDEX ... WHERE ... != ''` | 重复 `serial_no`/`asset_no` 插入失败 |

### 3.3 Phase 2：后端健壮性（3 天）

| 任务编号 | 对应问题 | 任务名称 | 工期 | 技术方案 | 验收标准 |
|---------|---------|---------|------|---------|----------|
| B-01 | P1-09 | 连接池错误分类修复（26 处） | 1h | 移除所有 `map_err(AppError::io)`，改用 `?` + `From` trait | `rg 'map_err\(AppError::io\)' src-tauri/src/` 无结果 |
| B-02 | P1-05 | insert 后 `.unwrap()` 修复（4 处） | 0.5h | 改用 `ok_or(AppError::not_found(id))?` | 无生产路径 `.unwrap()` |
| B-03 | P1-10 | `.ok()` 吞错误修复（7 处） | 1h | 区分"不存在"和"数据库错误" | 数据库错误不再被静默忽略 |
| B-04 | P1-14 | 导出命令异步化（5 个） | 1h | 改用 `#[tauri::command(async)]` + `tauri::async_runtime::spawn_blocking()` | 导出时 UI 不冻结 |
| B-05 | P1-13 | 修复 N+1 查询 | 0.5h | `export_racks_excel` 一次查询所有 devices + 内存分组 | 导出 100 机柜不再逐 rack 查询 |
| B-06 | P2-01 | SELECT 列列表去重（13 处） | 1h | 提取为常量 `DEVICE_COLUMNS: &str = "id, name, ..."` | 列列表只定义一次 |
| B-07 | P2-02 | row_to_* 映射函数统一（3 模块） | 1h | 提取为 `fn row_to_device(row: &Row) -> Result<Device>` 公共函数 | 映射逻辑只实现一次 |
| B-08 | P2-04 | 日期解析函数统一 | 0.5h | 提取为 `fn parse_optional_date(s: &str) -> Option<String>` 公共函数 | 日期解析逻辑只实现一次 |

本升级方案基于 `RackViz-v1.1-完整审计报告.md`，对 89 个审计发现（13 P0 + 55 P1 + 21 P2）制定了系统的修复计划，并新增了多个功能优化建议。

**关键路径**：Phase 0 → Phase 1 → Phase 2 → Phase 3 → 最终验收（约 10.5 天）

**可并行任务**：Phase 4（功能增强）可与 Phase 3（前端重构）并行开发。

**建议**：优先完成 Phase 0~3（安全、数据、后端、前端），确保 P0 问题全清，然后再根据资源情况决定是否实施 Phase 4 的所有功能增强。
