### 3.5 数据模型与 schema v5

```
rooms (机房)                    device_models (型号字典)
  │ 1                                  │ 1
  │ room_id  ON DELETE SET NULL        │ device_model_id  ON DELETE SET NULL
  ▼ N                                  ▼ N
racks (机柜) ──── 1:N ────► devices (设备)
  height_u (4–48U, 默认 42)     start_u / end_u / height_u
  row / col / view / sort_order  created_at / updated_at / deleted_at
```

**迁移链**

| 版本 | 内容 |
|:---:|---|
| v1 | 建 4 表 |
| v2 | 建 `settings` KV 表 |
| v3 | 7 索引 + 4 UNIQUE + 事务保护 |
| v4 | `devices.height_u` 固有高度列 + 回填 |
| **v5** | 4 表加 `created_at` / `updated_at`；`devices.deleted_at`（软删除）；**唯一索引重建为部分索引**（软删记录退出唯一约束）；新增 6 个索引 |

**关键语义**

- 外键全 `ON DELETE SET NULL` 软级联（**刻意设计：设备不丢失**）
- `devices.status`：`online` / `offline` / `unconfigured`（资源池）
- `device_models.type`：**8 种**（server / switch / router / storage / nas / security / loadbalancer / other）
- `start_u` / `end_u`：闭区间，1U 时相等，**NULL = 未上架**
- `height_u`：四级优先级 = 显式值 > U 位区间 > 型号高度 > 1
- DB 位置：`%LOCALAPPDATA%\com.rackviz.app\rackviz.db`；日志同级 `logs/`（按天轮转保留 7 天）

> 🔴 **v5 新增硬约束**：`uniq_devices_serial_no` / `uniq_devices_asset_no` 已改为
> `WHERE serial_no <> '' AND deleted_at IS NULL` 的**部分唯一索引**。
> **所有设备查询默认必须带 `deleted_at IS NULL`**，否则会把回收站里的记录查出来、也会误判重复。

### 3.9 二维码内容契约（N-14，最终版 · 勿随意变更）

**编码格式：多行 `字段名：字段值`，恒定 7 行，顺序不可变**（冒号为全角 `：` U+FF1A）：

```
设备名称：A-01-存储阵列-01
型号：Dell EMC Unity XT 480
IP地址：10.10.1.16;10.10.1.17
资产编号：ZC-2026-0006
序列号：SN-B-02-006
使用部门：研发中心
责任人：孙鹏
```

| 约束 | 说明 |
|---|---|
| 单一数据源 | 标签正文与二维码内容**共用 `buildQrRows()`**，保证「印着的」与「扫到的」逐字一致，改一处即同步 |
| 空字段 | **仍保留整行**（如 `使用部门：`），不得省略行、不得用 `-` 占位 |
| 脏数据 | 值中的 `\r` / `\n` **必须归一化为空格**，否则一行被劈成两行、破坏行结构 |
| IP 多值 | 半角 `;` 分隔，原样输出（`Device.ip_addresses` 本就是 `;` 分隔） |
| 解析 | `parseDeviceQr` 按行序 + 字段名严格匹配，行序错乱 / 字段名未知 / 行数不符一律返回 `null` |
| 历史格式 | `RV|a|b|c` 竖线格式与 v1 四段载荷**已彻底移除，无任何兼容**（用户确认不存在已打印旧标签） |

| 项 | 值 | 依据 |
|---|---|---|
| 纠错级别 | `M`（15%） | 打印标签需抗污损，**不降为 L** |
| 安静区 | **4 模块** | ISO/IEC 18004 规定；`qrcode.react` 的 `marginSize` 默认 0，曾误设为 2（`57ce44b` 修复） |
| 容量占用 | 198 字节 → **v10 / 53×53 模块** | UTF-8 实测；`size` 已含安静区，故安静区不影响布局 |
| 打印尺寸 | 132 CSS px ≈ **34.9 mm** | 打印块仅设 `@page margin:12mm`，未为标签设独立尺寸 |
| 每模块 | ≈ **0.57 mm** | 远高于 0.4 mm 可扫下限；即便按最保守的 25 mm 估算仍约 0.44 mm，亦可扫 |

> 📌 结论：7 字段（198B）相对 4 字段（127B，v8/45×45）仅多 1 个 QR 版本，**无需为密度砍字段**。
> 若日后新增字段，重算字节数并确认仍 ≤ v10（213B）；超过则需评估放大 `QR_SIZE` 或调整标签尺寸。
