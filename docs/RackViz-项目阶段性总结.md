## 二、第一阶段：立项与 v1.0（2026-05-27 ~ 05-28）

### 2.1 项目背景与动机

数据中心运维长期面临以下痛点：
- 机柜设备位置依赖 Excel 记录，不直观、易出错
- 设备上下架操作繁琐，需要同步更新多个文档
- 多人运维缺少操作审计记录
- 批量录入设备费时费力
- 数据散落各处，报表靠手动拼接

RackViz 的立项目标就是**用可视化手段解决数据中心设备管理的效率问题**。

### 2.2 技术选型（v1.0）

| 层级 | 技术选择 | 理由 |
|------|---------|------|
| 后端 | Python 3 + FastAPI | 快速开发，生态丰富 |
| 桌面容器 | pywebview | Python 原生桌面窗口方案 |
| 前端 | React 18 + Ant Design 5 | 企业级 UI 组件库 |
| 数据库 | SQLite | 轻量嵌入式，单机场景适合 |
| 构建 | Vite | 前端快速构建 |

### 2.3 v1.0 实现的功能

| 模块 | 功能 |
|------|------|
| 机柜可视化 | 42U 标准机柜网格、设备颜色编码、缩放控制、U 位使用率 |
| 设备台账 | 11 列可配置表格、列宽拖拽、多列排序、分页浏览 |
| 机房管理 | CRUD 操作、标签页导航 |
| 机柜管理 | 创建/编辑/删除机柜、自定义高度 |
| 设备型号 | 型号 CRUD、5 种设备类型彩色标签 |
| 数据导入 | Excel 基础导入 |
| 数据导出 | Excel 导出 |
| 主题 | Dark/Light 切换 |

### 2.4 v1.0 的局限与问题

| 问题 | 影响 |
|------|------|
| **安装包 100+ MB** | pywebview 打包体积庞大，分发困难 |
| **启动速度 3-5s** | Python 运行时 + FastAPI 冷启动慢 |
| **运行内存 150-240 MB** | Python 进程占用高 |
| **Mutex 串行访问** | SQLite 连接用 `threading.Lock` 保护，并发读性能差 |
| **pywebview 兼容性** | 不同平台 WebView 行为不一致 |
| **导入无查重** | 重复导入导致数据重复 |
| **拖拽不完善** | HTML5 拖拽在 pywebview 中表现不稳定 |

## 三、第二阶段：Tauri 重构评估（2026-06-09）

### 3.1 重构决策

v1.0 上线后暴露的性能与体验问题，促成了技术栈的全面升级决策。核心考量：

| 对比维度 | Python + pywebview | Rust + Tauri 2.x |
|---------|-------------------|------------------|
| 安装包 | 100+ MB | ~18 MB |
| 启动速度 | 3-5s | < 500ms |
| 运行内存 | 150-240 MB | 30-50 MB |
| 并发能力 | Mutex 串行 | r2d2 连接池 |
| 桌面集成 | 有限 | 原生对话框/托盘/快捷键/自动更新 |
| 安全性 | 无 CSP | Tauri 安全体系 |

### 3.2 方案设计过程

**第一轮：评估与质疑**

- 深入阅读全部源码（FastAPI 后端 4 个数据模型 + React 前端 RackView/DeviceList/RoomTabs）
- 统计前端 snake_case 字段引用 174 处
- 对原始重构方案提出 10 个关键问题：
  1. 连接池方案选型
  2. 数据库迁移机制
  3. 前后端文件传输方式
  4. 错误处理链设计
  5. camelCase 兼容性策略
  6. 测试策略
  7. PRAGMA 持久化
  8. Tauri 安全策略
  9. 前后端类型同步
  10. 发布与更新机制

**第二轮：方案重写（v1 → v2）**

将原始方案重写为优化版，关键改进：
- **r2d2 连接池** 替代 Mutex — 并发读性能提升 4x
- **文件路径传输** — 导出时 Rust 侧弹出原生保存对话框直接写文件，避免二进制 IPC
- **snake_case 序列化** — 前后端统一字段名，避免 174 处前端改动
- **版本化迁移** — 使用 `PRAGMA user_version` 管理
- **with_transaction 事务** — `BEGIN IMMEDIATE` / `COMMIT` / `ROLLBACK` 封装
- **分层错误链** — 7 种 AppError 错误码
- **Tauri 特有功能** — 托盘/快捷键/菜单/自动更新集成

**第三轮：实施手册编制**

产出三份指导文档：

| 文档 | 内容 |
|------|------|
| 重构实施手册 | 8 个 Sprint 的可执行任务序列、质量门禁命令、回滚策略、端到端验证矩阵 |
| 重构审计报告 | 发现 7 个问题（3 个 P0 + 2 个 P1 + 2 个 P2），有条件通过 |
| 功能清单与优化建议 | 60 项功能梳理 + 32 条优化建议 + 8 项 Tauri 新能力 |

## 四、第三阶段：Tauri 重构实施（2026-06-10）

### 4.1 核心架构改造

#### 后端改造

| 改造项 | 旧方案 | 新方案 | 改动量 |
|--------|--------|--------|--------|
| 数据库连接 | `Mutex<Connection>` | `r2d2::Pool<SqliteConnectionManager>` | state.rs 重写 |
| 连接获取 | `state.conn.lock()` | `state.pool.get()` | 5 个命令文件 |
| 事务管理 | 无 | `with_transaction` 封装 | db/mod.rs |
| PRAGMA 持久化 | 无 | `RackVizConnectionCustomizer` | state.rs |
| Excel 导入 | 基础 | calamine 0.25 + `find_or_create` + 事务保护 | excel.rs 重写 |
| Excel 导出 | 基础 | rust_xlsxwriter + 关联数据填充 | excel.rs 重写 |
| 对话框 | HTML input | Tauri 2.x `app.dialog().file()` | commands/exports.rs |
| 日志 | env_logger | flexi_logger 0.29 + 运行时切换 | 新增 logging.rs |
| 设置 | 无 | KV settings 表 + 3 个命令 | 新增 db/settings.rs |

#### 前端改造

| 改造项 | 旧方案 | 新方案 | 改动量 |
|--------|--------|--------|--------|
| API 调用 | HTTP fetch (`api/client.ts`) | Tauri `invoke()` (`tauri-api.ts`) | 4 个 hooks + tauri-api.ts |
| 文件选择 | HTML input | Tauri dialog 原生对话框 | DeviceList.tsx |
| 状态管理 | useApiList 基础版 | useRef 稳定引用 + 乐观更新 | useApiList.ts 重写 |

#### 数据库改造

| 改造项 | 旧方案 | 新方案 |
|--------|--------|--------|
| 并发访问 | `threading.Lock` 串行 | r2d2 连接池 (max_size=4) |
| WAL 模式 | 未设置 | `PRAGMA journal_mode=WAL` |
| busy_timeout | 未设置 | 5000ms |
| 外键约束 | 未启用 | `PRAGMA foreign_keys=ON` |
| 迁移机制 | 无 | v0→v1→v2 版本化迁移 |

### 4.2 遇到的技术难题与解决

| 难题 | 解决方案 | 教训 |
|------|---------|------|
| `r2d2_rusqlite` crate 不存在 | 正确 crate 名是 `r2d2_sqlite` | 搜索 crate 名要确认 registry |
| calamine 0.25 `DataType` 改名为 `Data` | 手动写 `cell_to_string()` 辅助函数 | 升级依赖先看 changelog |
| Tauri 2.x dialog 返回 `Option<FilePath>` | match 转换为 PathBuf | Tauri 2.x API 与 1.x 差异大 |
| `with_transaction` 跨模块导入 | `pub use crate::state::with_transaction` 重导出 | Rust 模块可见性规则 |
| sed 多行替换搞乱代码 | 改用 Python 字符串替换 | 不要用 sed 处理多行 |

## 八、关键经验与教训

### 8.1 技术选型

| 经验 | 详情 |
|------|------|
| **Tauri 替代 Electron/pywebview** | 安装包小 5x+、启动快 10x、内存低 80%，是桌面应用的未来方向 |
| **r2d2 连接池** | 并发性能远超 Mutex，且通过 ConnectionCustomizer 持久化 PRAGMA |
| **snake_case 序列化统一** | 避免了 174 处前端字段引用改动，极大降低迁移成本 |
| **文件路径传输** | 导出场景用原生对话框直接写文件，比二进制 IPC 序列化高效得多 |

### 8.2 开发流程

| 教训 | 详情 |
|------|------|
| **先看 changelog 再升级** | calamine 0.25 的 API 改名导致编译失败 |
| **不要用 sed 处理多行** | 用 Python 字符串替换更可靠 |
| **Tauri build vs cargo build** | 必须用 `cargo tauri build` 才能嵌入前端资源 |
| **CSP 不应关闭** | 开发时为方便关闭 CSP，但生产必须配置 |
| **HTML5 拖拽 + Tauri** | 需要同时禁用 Tauri 拦截和正确使用 dataTransfer API |

### 8.3 架构决策

| 决策 | 理由 | 潜在问题 |
|------|------|---------|
| COALESCE 部分更新 | Option 字段自然映射 | 无法置空（已识别） |
| 软级联删除 | 删除 Room/Rack/Model 不丢设备 | 设备可能无归属 |
| flexi_logger | 运行时切换日志级别 | reconfigure 不支持重建文件输出器 |
| useRef 稳定化 | 解决无限刷新 | 增加代码复杂度 |
