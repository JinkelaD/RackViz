## 一、列契约（严格对齐 `src-tauri/src/excel.rs`）

导入路径**按列序号 0-14 读取，无表头识别**，第 0 行固定被当作表头跳过。文件表头仅作可读性用途，与导入逻辑无关。

| 列序 | 表头 | 导入语义 | 本数据取值 |
|:---:|------|---------|-----------|
| 0 | 设备名称 | `name`；为空则整行被 `continue` 丢弃 | `{机柜}-{角色}-{序号}`，如 `A-01-应用服务器-01` |

## 三、⚠️ 两个系统限制（务必先读）

### 1. 设备类型列（N-21 已落地，当前行为）

`device_models.type` 是**型号**的属性。导入格式第 16 列「设备类型」经 `find_or_create_model(name, type)` 在新建型号时使用该类型。

| 场景 | 行为 |
|------|------|
| 类型在 8 种枚举内 | **关联** —— 型号按该类型落库 |
| 类型为未知值或空 | **兜底** 为 `other`，不阻断导入，结果中告警 |
| 同名型号已存在 | **复用，且不覆盖其既有类型**（保护你在「型号管理」里手工修正的结果；重复导入保持幂等） |

### 2. 机柜规格**无法通过导入设置**

`find_or_create_rack`（`db/racks.rs`）自动创建的机柜**一律 42U**。

**若你想测试多种机柜规格，必须先建机柜、再导入**——`find_or_create_rack` 会先按名称查找，命中则复用你建的那个（含自定义高度）。各机柜所需最低高度：

| 机柜 | 最低高度 | 建议设定 |
|------|:---:|------|
| A-02 | **37U** | 42U / 47U |
| A-01、B-01 | 17U | 42U / 24U |
| B-02 | 16U | 24U |
| A-03、DR-01 | 15U | 24U |
| B-03、DR-02、NET-01、NET-02、NET-03 | 13U | 24U |
| DR-03 | 11U | 24U |

> 例：先在界面创建 `DR-03`、`NET-02`、`NET-03` 三个 **24U** 机柜，再导入，即可同时看到 42U 与 24U 两种规格的渲染差异。

### 3. 机房列（N-05 已落地，当前行为）

导入时若勾选「关联机房」选项，第 2 列机房的值会自动创建机房并挂接机柜；未勾选则机柜 `room_id` 为 NULL，可在机柜视图手动分配。

## 五、使用建议

1. **建议在全新数据库上导入主文件**。若库中已有数据，序列号/资产编号可能撞车。
2. **测查重最简方式**：把主文件**再导入一次** → 100 条应全部被跳过（`导入完成：成功 0 条，跳过重复 100 条`）。因为序列号、资产编号、同机柜同名三个键全部命中。
3. **边界文件的 4 条容错用例**会真实写库，其中 `EDGE-资源池设备-01` 与 `EDGE-未知型号-01` 落在"资源池"（未上架）；`EDGE-非法日期-01` 的日期会**静默变 NULL**（`parse_optional_date` 解析失败返回 `None`，不报错——这本身是一个可被验证的行为）。
4. **⚠️ 不要用 Excel 打开后另存再导入**。另存会把 `2025-01-01` 这类字符串转成日期类型，而 `cell_to_string` 对 `DateTime` 分支返回空串，日期会全部变 NULL。请直接使用本目录的原始文件。
